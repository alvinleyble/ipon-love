# Mission: Model & Effort Selection for AI-Assisted Development

## Why
Building Ipon, Love with Claude Code costs real money and real time. Choosing the wrong model (Opus when Sonnet suffices, or Sonnet when Opus is needed) either wastes budget or produces designs that need rework. The goal is to make model + effort decisions automatically and correctly, without reading CLAUDE.md every time.

## Success looks like
- Given any new Ipon, Love slice (or any future project), can immediately name the right model and pre-build effort level with a one-sentence rationale — before looking at CLAUDE.md
- Can recognize the signals that separate "pattern-follow" from "design" tasks without a checklist
- Rarely second-guesses the call mid-task, because the framework is internalized, not just memorized

## Constraints
- Learning is grounded in Ipon, Love — abstract theory without project anchors won't stick
- Lessons should be completable quickly (working on a side project, not studying full-time)
- No prior AI-engineering theory assumed — but Alvin already knows how the project is structured

## Out of scope
- General prompt engineering
- LLM benchmarks or technical model internals
- Other providers (OpenAI, Gemini) — this is Claude-specific
