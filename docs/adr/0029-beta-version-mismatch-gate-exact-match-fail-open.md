# Beta version-mismatch gate: exact-match, hard block, fail-open

**Context.** Beta testers have no version-check today — nothing stops them from testing against a stale build while Alvin assumes bug reports reflect the latest shipped code. `versionCode` (`app/build.gradle.kts:28`) is the only version signal in the app; there's no Supabase table, no remote-config mechanism.

**Decision.** A single-row `app_release_info` Supabase table (public-read RLS, no client write, manually bumped by Alvin per release) holds the required version code. The app compares its installed `versionCode` against that row using **exact-match**, not a floor (`installed < required`) — the actual goal is every tester on the identical build, for comparable bug reports, not merely "not behind." This means Alvin must bump the row on his own device before a new build reaches testers, or he'd block himself too. A mismatch renders a hard, non-dismissable blocking `Dialog` (same shape as `AppLock`'s), with an "Update" button opening `https://play.google.com/store/apps/details?id=com.iponlove.app` (chosen over a `market://` deep link because it degrades gracefully through a browser if the Play Store app isn't present — every tester who could see this dialog is already enrolled in internal testing, since that's the only way to have the app installed at all). The check runs on the same foreground/resume lifecycle plumbing `AppLock` already uses, gated behind `BuildConfig.IS_BETA_BUILD`. A failed version-check call (offline, Supabase down) fails **open** — the whole app never blocks on this non-core network call, consistent with the app's offline-first principle.

**Rejected:** floor semantics (`installed >= required`) — the more standard shape, and it avoids blocking someone who's ahead of the published row, but doesn't serve the actual goal here (uniform builds for comparable bug reports), and the "ahead" edge case barely matters since Alvin is the only one shipping builds right now.
