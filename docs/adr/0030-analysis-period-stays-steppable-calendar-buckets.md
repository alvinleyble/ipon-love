# Analysis period stays steppable calendar buckets, not crypto-style trailing windows

**Context.** Alvin asked for a "crypto-app-style" redesign of the Analysis time-range filter (1D/1W/1M/3M/6M/12M/ALL TIME), which reads as an obvious match for the existing enum's `AnalysisPeriod` values. But there are two genuinely different things a "period" can mean: today's `DAY/WEEK/MONTH` are **steppable calendar buckets** — `PeriodStepper` pages the anchor date to the literal previous/next calendar day/week/month (e.g. "June 2026" → "July 2026") — while crypto-app presets are **trailing windows anchored to now** ("3M" = the last 90 days ending today; there's no "previous 3M" to step to). Bolting trailing-window presets onto the existing stepper model without picking one would produce a confusing hybrid.

**Decision.** Extend the *existing* steppable-calendar-bucket model with more granularities — Quarter, Semi-annual, Annual, All-time — alongside the existing Day/Week/Month, all pageable via the same `PeriodStepper` mechanism (a Quarter steps between calendar quarters, a Year between calendar years, etc.). Explicitly **not** trailing windows: reviewing a specific past period ("what did March look like") is a real, common use case for a personal-finance app, unlike a price chart where only the trend matters. Labels are kept short (crypto-style abbreviations or similar) purely for layout reasons — cramming 7 options into one row requires a lightweight segmented tab control (not Material3 `FilterChip`s, whose padding/border only comfortably fit 3), wrapped in a horizontally-scrollable row as a safety net for narrow devices or large system font sizes. A short label like "3M" does **not** imply trailing-window semantics here, even though that's its common meaning elsewhere (Coinbase, Robinhood, etc.) — this is a deliberate, documented deviation from that convention. All-time's window start is a fixed, arbitrarily-early `Instant`, not a query for the user's actual earliest transaction — simpler, and there's no realistic perf concern at this app's data volumes.

**Rejected:** replacing the stepper model with true trailing windows (matches crypto apps exactly, but loses the "browse a specific past month" ability); a two-row or dropdown layout for the 7 options (a two-row layout doubles the vertical footprint this control eats, working against the actual goal of feeling more compact; a dropdown hides all options behind one tap, a worse default for a control used this frequently).
