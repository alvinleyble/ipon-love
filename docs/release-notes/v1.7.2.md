# v1.7.2 Release Notes

**Note:** this is a **single-item security-hardening release** (v1.7.2 Item 1 / [ADR-0060](../adr/0060-entitlement-columns-are-rpc-write-only.md)) with **no user-visible feature or UI change**. The entitlement columns on the `users` row can no longer be written directly — only through a validating RPC. Nothing a tester can see changed, so the notes are deliberately thin; don't pad them with v1.7.1 carryover.

## Play Store (≤500 chars, bullet points)

- Behind-the-scenes security and reliability improvements

## Full

- 🔒 Security hardening for account and subscription data — no changes to how the app looks or works

## Internal (not for the Play listing)

- Entitlement columns (`is_premium`, `premium_until`, `entitlement_source`, `entitlement_checked_at`) are now **RPC-write-only**: the `authenticated` role's table-level `UPDATE` on `users` is dropped and replaced with an **allowlist grant** on the 9 profile columns, so a forged `update({is_premium: true})` from a browser dev console (the vector the Q4 web app would have opened) is rejected with `42501`.
- The client `users` push was split accordingly — `UserPushDto` omits the four locked columns, and `UserTableSyncer.remotePush()` calls `set_self_entitlement` alongside the profile upsert, riding the existing dirty-row outbox so entitlement writes still survive being made offline.
- **Receipt validation is deliberately NOT in this release.** The RPC is a passthrough: it raises the bar from "write any column" to "call the RPC correctly," and does not yet verify a Play purchase. Real validation must land before enforcement flip-day, the web purchase path (W7), or AI credits — whichever comes first.
- **Watch out when adding a `users` column:** it now needs a matching `grant update (...)` in the migration, or that field will silently stop syncing.
